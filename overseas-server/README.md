# SubFlux 国外主服务

部署在国外的聚合面板：拉取多个订阅、解析节点、做画像与检测、按条件筛选，并生成多客户端订阅。

## 启动

```bash
cd overseas-server
npm install
./start.sh      # 后台启动，日志写入 data/logs/app-YYYY-MM-DD.log（保留 24 小时）
# 或 node server.js
```

默认监听 `0.0.0.0:8888`，打开 `http://<主机IP>:8888` 会跳到登录页。默认账号 `admin` / `subflux`，请用环境变量覆盖。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8888` | 监听端口 |
| `HOST` | `0.0.0.0` | 绑定地址 |
| `DATA_DIR` | `./data` | 数据目录（db.json、logs、密钥） |
| `SUBFLUX_USERNAME` | `admin` | 面板登录用户名 |
| `SUBFLUX_PASSWORD` | `subflux` | 面板登录密码，部署后请立即修改 |
| `SUBFLUX_SESSION_SECRET` | 自动生成 | 会话签名密钥（≥16 字符），留空写入 `data/.session-secret` |
| `SUBFLUX_SECRET_KEY` | 自动生成 | 敏感字段加密密钥（≥16 字符），留空写入 `data/.secret-key`；设置后不要更换 |
| `MIHOMO_BIN` | 自动查找 | 站点检测引擎路径；未设置时依次尝试 `/opt/mihomo/mihomo`（compose 默认下载位置）→ `bin/mihomo` |
| `PROXYCHECK_KEY` | 空 | ProxyCheck API Key（可选），留空使用免费额度 |

`bin/mihomo` 不入库（约 55MB，区分架构），首次部署按 `bin/README.md` 下载，或设置 `MIHOMO_BIN`。引擎查找顺序是：设置里的路径 → `MIHOMO_BIN` → `/opt/mihomo/mihomo`（Docker Compose 默认下载位置）→ 项目内置 `bin/mihomo`；面板「设置 → 站点解锁检测」里可以看到当前解析到哪个路径。找不到引擎时面板仍可启动，但站点检测、自动站点检测和 CN 实际检测不可用。

## 使用流程

1. **订阅源** → 添加订阅链接或粘贴 Clash / Base64 / 节点文本。可设置刷新周期（不限上限，快捷按钮含 7 / 14 / 30 天）、User-Agent，以及拉取方式（直连 / 走节点池里的某个节点 / 指定外部代理地址）；也可以关闭「自动刷新」，让这个源只在手动点刷新时才抓取。
2. **节点池** → 测速（TCP 入口延迟）、IP 画像、站点检测、CN 实际检测。支持按来源、协议、地区、类型、站点、CN 连通、质量、延迟筛选。
3. **输出订阅** → 新建输出，选择回退格式和筛选条件；「最多输出节点」控制每个订阅返回的条数（填 0 表示不限制）。卡片上的复制图标可以基于当前配置新建一个副本（名称自动加「副本」，推送默认关闭），改完保存就是一条独立订阅。复制自动链接或扫码导入客户端。

输出链接：

```text
/sub/<token>           自动识别客户端（推荐）
/sub/<token>/clash
/sub/<token>/singbox
/sub/<token>/base64
/sub/<token>/plain
```

「设置 → 订阅访问地址」可以填订阅链接使用的前缀（例如 `https://sub.example.com` 或 `http://203.0.113.10:8888`），留空则用浏览器当前地址；二维码和复制出来的链接都会用这个前缀。

`/sub/<token>` 按 User-Agent 判断客户端并设置 `Vary: User-Agent`，响应头 `x-subflux-format` 表示实际返回的格式。回退格式仅在 UA 无法识别时使用。每次请求都会按当前节点池和筛选条件实时生成，不缓存；需要临时限制条数时可以在链接后加 `?limit=100`。

## 刷新后自动检测

「设置 → 刷新与检测」可开启：

- **自动 IP 画像**：刷新后为缺少数据的节点补 ASN、代理 / VPN 风险与质量分。
- **自动连通 / 延迟检测**：刷新后重新测该源全部节点的 TCP 入口端口；HY2 / TUIC / WireGuard 等 UDP 协议跳过 TCP 探测。
- **自动站点检测**：只对缺少站点结果的新节点真实访问已启用站点，不设数量上限；手动检测会覆盖当前筛选（或勾选）的全部节点。

测速覆盖全部节点；站点检测和 IP 画像只补缺数据的节点，都不设数量上限。自动任务后台执行，不阻塞刷新。UDP 节点的实际连通以站点检测结果为准。

质量分由 IP 类型、ProxyCheck 的代理 / VPN / 风险值（0–100）和延迟共同决定：`risk` ≥ 75、VPN 或 Tor 会明显压低分数，被识别为代理的节点最高 50 分。ProxyCheck 免费无 Key 每天 100 个 IP，注册免费 Key 后 1,000 个/天；可在「设置 → 刷新与检测」填 Key 或调整每日上限（0 关闭），额度用完时本轮自动停止，剩余 IP 下次补全。评分是自建口径，和 iplark 的原生 IP / 滥用数据库评分不会完全一致。

关闭「自动刷新」的订阅源不参与定时任务，卡片上会标「仅手动刷新」；点卡片上的刷新按钮或「全部刷新」仍会抓取，只是抓完不排下一次。

## 登录认证

面板页面和所有 `/api` 接口都需要登录；订阅输出 `/sub/<token>` 仍使用令牌认证，客户端不需要账号。账号通过环境变量配置：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SUBFLUX_USERNAME` | `admin` | 登录用户名 |
| `SUBFLUX_PASSWORD` | `subflux` | 登录密码，至少 4 位 |
| `SUBFLUX_SESSION_SECRET` | 自动生成 | 会话 Cookie 签名密钥，留空则生成 `data/.session-secret` |

- 登录后签发 7 天有效的 HttpOnly + SameSite=Lax 会话 Cookie；反向代理走 HTTPS 时自动加 `Secure`。
- 所有写接口校验 `x-csrf-token`（前端自动携带），登录失败按 IP 限速：10 分钟内 5 次失败封禁 15 分钟。
- 侧栏底部「退出登录」会清除会话并回到登录页。

## 数据加密与日志

- **加密范围**：`settings.chinaProbeToken`、`settings.fetchProxy`、订阅源的 URL / 文本内容 / 拉取代理、节点的 `raw` 与 `uri`、推送目标的 URL / AccessKey / 请求头。
- **算法**：AES-256-GCM，落盘格式 `enc:v1:<base64>`；内存中仍是明文，读写对业务透明。
- **密钥**：默认 `data/.secret-key`（首次启动生成，权限 0600）；也可以用 `SUBFLUX_SECRET_KEY` 指定。**更换密钥会导致旧数据无法解密，服务会直接报错退出而不是覆盖数据**；迁移或备份时必须把 `.secret-key` 与 `db.json` 一起带走。
- **日志**：应用日志写到 `data/logs/app-YYYY-MM-DD.log`，启动时和每小时清理超过 24 小时的文件；`start.sh` 把标准输出写入 `data/logs/boot.log`（每次启动覆盖）。Docker 部署额外由 compose 限制 `max-size=10m`、`max-file=1`。

## 定时测速与任务中心

任务中心里运行中的延迟测速、站点检测、CN 检测都可以点「取消」，已完成的节点会保留结果。

「设置 → 定时测速」可以按固定间隔重新测所有节点的 TCP 入口延迟，默认开启、60 分钟一次；间隔可自定义（快捷 15 分 / 30 分 / 1 小时 / 3 小时 / 6 小时 / 12 小时 / 24 小时）。「测速并发」控制同时探测的节点数（1–64，默认 16），超时时间用同一页的「TCP 测速超时」（默认 2500 ms）。

「任务中心」（侧栏 `#/tasks`）显示正在运行的延迟测速、站点检测、CN 检测、订阅刷新与定时推送，以及进度、并发、超时和下次执行时间，也可以在这里一键「立即测速全部」。

调度模型：单个 30 秒 tick 顺序检查各任务的下次执行时间。延迟测速、站点检测、CN 检测各自同时只跑一个，后来的任务排队等待；不同订阅源的刷新可以并行，刷新和检测也可以同时进行。同一订阅源不会被重复刷新。下次执行时间会持久化，服务重启后不会丢计划；重启时已到期的任务会在下一个 tick 立即补跑。

## 站点解锁检测

通过本地 Mihomo 让节点真实访问站点，默认 5 项：

| 站点 | 简写 |
| --- | --- |
| YouTube | `YT` |
| ChatGPT | `GPT` |
| Claude | `CL` |
| Grok | `GRK` |
| Gemini | `GEM` |

- 可在设置中增删站点、修改简写和检测地址。
- 只有明确支持（HTTP 2xx/3xx 且非挑战页）才写入节点名；超时、Cloudflare 挑战等不确定结果不会写成支持。
- 节点名默认追加 `[YT·GPT]`；模板含 `{sites}` 时按模板位置插入。
- 输出订阅的站点过滤要求所选站点**全部**为支持。

## 分流规则

默认顺序：

1. 私网 / 回环 / `.local` / `.lan` 直连
2. 自定义规则（全局 + 单订阅，优先级最高）
3. OpenAI / Claude / Gemini / Grok / YouTube 走手动选择
4. 可选广告拦截
5. 内置 159 条国内常见域名显式直连（`lib/cn-direct.js`）
6. `.cn` + `GEOSITE,cn` + `GEOIP,CN` 兜底
7. `MATCH` 走手动选择

显式直连列表覆盖百度、腾讯、阿里、字节、网易、京东、B 站、知乎、美团、12306、运营商、银行等，避免 GeoSite 数据缺失时误代理国内站点。自定义规则使用可视化编辑器，不需要手写语法。

Sing-box 会转换常用规则并使用远程 `geosite-cn` / `geoip-cn` rule-set；不支持的语法会在预览中提示。

## 订阅拉取代理

订阅源可以单独选择拉取方式：

- **直连**：服务器直接请求订阅站（默认）。
- **节点池节点**：选一个已有节点作为出口。面板会用内置 Mihomo 临时拉起单节点代理，因此 vmess / vless / trojan / ss / hysteria2 等协议都能用；节点被删除后刷新会提示重新选择。
- **外部代理地址**：填 `http://`、`https://` 或 `socks5://`（socks5 由 Mihomo 转成本地混合端口）。留空则回退到「设置 → 刷新与检测 → 订阅拉取代理」。

改了拉取方式会立刻触发一次抓取，方便确认能不能连通。

## 定时推送

每个输出订阅可以单独开启「定时推送」，到点生成该订阅并推送到一个或多个目标（最多 5 个）：

- **本地文件**：写到服务器路径，例如 `/data/sub/subflux.yaml`；目录会自动创建，先写临时文件再替换，避免读到半截内容。
- **HTTP 地址**：PUT 或 POST 到指定 URL，可附加 `Authorization` 等请求头，适合对象存储预签名地址、WebDAV 网关或自己的接收端。
- **对象存储**：支持阿里云 OSS（原生签名）和 S3 兼容存储（R2 / MinIO / AWS，SigV4）。填写 Endpoint、Bucket、AccessKey、对象路径；S3 兼容还需要 Region。

推送间隔独立于订阅源刷新间隔，可以按分钟设置，也可以设到任意长；推送失败只会标记在订阅卡片上，不影响订阅本身。卡片上的上传图标可以随时立即推送。

注意：AccessKey Secret 以明文保存在 `data/db.json`，请限制面板访问范围并保管好备份文件。

## 导出与导入订阅源

订阅源页面的「导出」会把全部订阅源（名称、链接、粘贴内容、刷新周期、自动刷新开关、拉取代理）写成 JSON 文件；「导入」支持选择该文件或直接粘贴 JSON，按订阅链接 / 粘贴内容去重后合并，不会覆盖现有订阅源。导入的 URL 源会在后台自动抓取。

导出文件包含订阅链接本身（通常带有订阅令牌），不要随手分享。

## 中国连通检测

主服务在国外无法直接判断节点在国内是否可达，需要配合 `../china-probe/` 部署国内探针。配置后在节点池使用「CN 实际」执行实际代理检测，详见 [../china-probe/README.md](../china-probe/README.md)。

## 数据与安全

- 所有数据保存在 `data/db.json`，包含订阅地址、节点信息和输出令牌。
- 面板没有登录鉴权，不要直接暴露到公网；需要外部访问时用反向代理加认证或仅走内网 / Tailscale。
- 定期备份 `data/`；升级前先停止服务。
